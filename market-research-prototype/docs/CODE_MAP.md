# Code map — what every script does

Generated by reading the repo's own AST (module docstrings, public symbols, import graph),
2026-07-28. **131 production modules, 32,129 lines. 137 test modules, 24,405 lines** — a test
suite slightly smaller than the code it covers, which for a system whose product is *numbers a
buyer trusts* is roughly the right shape.

---

## How to hold it in your head

Six layers. Data flows down the page; nothing below imports anything above it.

```
  ENTRY        cli.py   api.py   intake.py            "a human asks for a report"
                 │
  ORCHESTRATION  plan.py (2,619 lines — the spine)    "run these 14 steps in order"
                 │        orchestrator/  capabilities/  harness/  agents/
                 │
  DOMAIN STEPS   discover  market_sizing  four_ps  pricing  financials  …  (39 root modules)
                 │                                         "compute one section"
  SKILLS         skills/            @skill               "compose tools, declare produces/consumes"
                 │
  TOOLS          tools/             @tool                "one primitive I/O call"
                 │
  FOUNDATION     llm  logger  cache  net  scrape/  sources  errors
```

The measured fan-in confirms it — `logger` 49, `llm` 34, `tools` 29, `skills` 22, `sources` 12,
`scrape` 11, `cache` 10. Those are the real load-bearing modules.

Cross-cutting, sitting beside all six: `persistence/` (what happened), `report/` (what the buyer
sees), `gates.py` (is it true), `context/` (what every prompt carries), `config/`, `model/`.

## 2. Orchestration — the spine, and it's the biggest problem in the repo

**`plan.py` (2,619 lines)** is the pipeline. `run_plan` alone is ~989 lines with **28
`try/except` blocks and 71 `if` statements**. Every step is called inline, guarded inline,
checkpointed inline.

It didn't have to be this way. `skills/pipeline_steps.py` declares the same 10 steps as
registered skills *with a produces/consumes dependency graph* — and **no production module calls
any of them**. The declarative layer exists and is bypassed, so every step is wired twice. That
is the honest answer to "why is our orchestrator so long compared to Claude Code or OpenHands."
Tracked as harness item 4 in [HARNESS_STATE.md](HARNESS_STATE.md); `test_one_orchestrator.py`
pins the gap so it cannot grow.

## 3. Domain steps — one module per report section

These are the 39 root modules. Each computes one thing and returns a dict.

**Discovery & competitors**
- `discover.py` (1,112) — the competitor set. Trend momentum + review velocity, enrichment, then LLM synthesis. `_set_canonical_density()` here is the single owner of the three roster numbers (count, active-momentum, average score).
- `clustering.py` (425) — embeds competitor descriptions, k-means + PCA, labels the axes, finds whitespace. Needs *descriptions*; silently produced nothing when the roster was OSM names only.
- `differentiators.py` (435) — differentiators + market gaps.
- `competitor_pricing.py` (237), `firmographics.py` (434) — price and firmographic enrichment.
- `place.py` (150) — go-to-market channel detection.

**Sizing** — the part that most needs to be right
- `market_sizing.py` (806) — the legacy LLM-based TAM/SAM/SOM. `estimate_market_size` is 451 lines. Still the default path.
- `skills/sizing/` — the deterministic replacement ("the numbers-right engine"): `classify.py` decides the scale, `dispatch.py` routes, and `hyperlocal.py` (427) / `regional.py` / `national_digital.py` are the three engines. `validate.py` (295) is the mandatory arithmetic gate; `bottom_up.py` grounds a figure in a live count.
- `macro_anchors.py` (434) — macro series for credibility.

**Customers & pricing**
- `customer_universe.py` (958) — real B2B companies as a countable universe.
- `segment_scoring.py` (241), `personas.py` (148), `taste.py` (408) — segment ranking, personas, customer-voice decoding.
- `pricing.py` (418) — MaxDiff + Van Westendorp simulation, benchmark table, break-even.
- `economics.py` (375) — CLV, CAC target, EVC, sensitivity.
- `business_model.py` (295) — classifies monetization and blocks model bleed (a per-unit venture must never be shown subscription churn).

**Output**
- `four_ps.py` (1,167) — the 4Ps narrative *and* the viability score. Also home to the guardrail directives every section prompt carries.
- `financials.py` (328) — 3-year scenarios.
- `charts.py` (266) — inline SVG, no chart library.

| `tools/econ.py` | BLS CEX household spend. |

| `tools/customer_voice.py` | Reddit / HN / StackExchange / dev.to / Lobsters mentions. |
| `tools/trend.py`, `social.py`, `ads.py` | Google Trends, Instagram, Meta Ad Library. |
| `tools/domain.py` | Parked-domain detection, domain resolution and age. |
| `tools/firmographic.py` | Wikidata + GitHub + LLM-fallback enrichment. Needs `brand + domain`. |
| `tools/registry.py` (380) | The `@tool` decorator and the `Evidence` type every tool returns. |

**`Evidence` is the most important type in the repo.** Every tool returns
`Evidence(source, category, count, payload, error, skeleton, cost_meta)`. `skeleton=True` means
"I could not get real data" — the distinction between *measured* and *absent* lives here, and
most of this codebase's historical bugs were something reading `payload` without checking
`skeleton`.

## 10. Benchmarks

`benchmarks/score.py` (709) scores a run against professional reference reports (coverage, TAM,
CAGR). `prose_judge.py` runs head-to-head against consulting prose; `judge_alignment.py`
measures whether the judge itself is stable across models and reruns — a judge nobody audits is
just another opinion.

## The five conventions worth knowing before you change anything

1. **`Evidence.skeleton`** — "no real data" is a first-class state, not an empty payload.
2. **`Finding.ok is None`** — not-applicable is not a pass. Most historical bugs here were a
   check that couldn't run reading as a check that passed.
3. **`data_origin`** — every figure records whether it was fetched, computed, scraped, or
   narrated. A figure may not cite a statistical agency without one (gate D53).
4. **One owner per number** — `_set_canonical_density` owns the roster's three numbers,
   `report/forecast.py` owns the sizing tables. Two writers means eventual disagreement.
5. **Python computes, LLM narrates** — where a deterministic script exists it must run, and the
   classifier's choice of script is binding (gate D52).

## Where the bodies are buried

- `plan.py:run_plan` — 989 lines, and the declarative alternative in
  `skills/pipeline_steps.py` is inert. Biggest outstanding refactor.
- `market_sizing.py:estimate_market_size` — 451 lines of LLM sizing, still the default while
  `skills/sizing/` sits beside it.
- 15 registered tools and 14 registered skills are unreachable from production. The dead tools
  are disproportionately the *grounding* ones.
- `schema.py` (175) — Pydantic context models, largely superseded.
- Anything Census-backed is dark until `CENSUS_API_KEY` is set; it is free, and it is currently
  the highest-leverage change available to a human on this project.
